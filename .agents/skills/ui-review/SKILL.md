# UI review

## Обязательное чтение

Прочитайте [`UI_GUIDELINES.md`](../../../docs/architecture/UI_GUIDELINES.md) как
главный источник истины по интерфейсу, затем [`design-principles.md`](../../../docs/architecture/design-principles.md),
релевантный документ сущности, существующие компоненты в `src/components/ui/` и
`src/components/entity/`. Перед изменением Next.js-кода прочитайте относящееся
руководство в `node_modules/next/dist/docs/`.

## Алгоритм

1. Определите существующий шаблон, компонент и данные, которые уже решают часть
   задачи. Не создавайте параллельную Design System или хардкод конкретной сущности.
   При конфликте локальной идеи с `UI_GUIDELINES.md` верен `UI_GUIDELINES.md`.
2. Сохраните структуру и высоту повторяемых карточек; контекстные состояния выводите
   переиспользуемым компонентом вне карточки, если это требуется сетке.
3. Используйте существующие токены, `Card`, типографику, иконки и responsive-паттерны.
4. Проверьте desktop и узкую ширину: переносы, обрезание, фокус, видимость ссылок,
   отсутствие лишних пустых зон и визуальную связь связанных блоков.
5. Проверьте состояние без данных, с одной записью и с несколькими связанными
   записями; не добавляйте пустые разделы.
6. Выполните typecheck, целевой lint и production build; для визуальной задачи
   дополнительно проверьте работающий интерфейс браузером.
