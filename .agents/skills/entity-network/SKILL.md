# Entity network

## Граница ответственности

Аудируйте полноту сети после изменения сущности. Не добавляйте связи
автоматически: `knowledge-graph` отвечает за создание и отображение конкретной
связи, а этот Skill формирует список отсутствующих или сомнительных отношений.

## Обязательное чтение

Прочитайте [`graph-model.md`](../../../docs/architecture/graph-model.md),
[`overview.md`](../../../docs/architecture/overview.md), документ изменённой
сущности в [`docs/architecture/`](../../../docs/architecture/) и фактическую
[`prisma/schema.prisma`](../../../prisma/schema.prisma).

## Алгоритм

1. Назовите изменённую сущность, её тип, slug, публичный URL и источник данных.
2. Проверьте возможные связи со всеми предметными типами: врач, клиника,
   оборудование, процедура, заболевание, расследование, новость, публикация,
   научная работа и документ.
3. Для каждой возможной связи определите статус: подтверждена, отсутствует в
   источниках, намеренно не нужна, требует проверки или уже выражена другой
   связью графа.
4. Проверьте обратное отображение: страница второй сущности должна уметь показать
   связь, если она будет добавлена через существующий владелец данных.
5. Отдельно отметьте недопустимые выводы: наличие оборудования не доказывает
   процедуру, новость не доказывает нарушение, публикация не доказывает врача
   без прямой атрибуции.
6. Сформируйте рекомендации, но не меняйте данные без отдельного задания или
   явного перехода к `knowledge-graph`.
7. В отчёте разделите обязательные связи для полноты, полезные связи для
   навигации и связи, которые нельзя добавлять из-за отсутствия источника.
