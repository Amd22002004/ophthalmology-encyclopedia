# Модель `Equipment` — ЗАВЕРШЕНА И ЗАФИКСИРОВАНА

> ## 🔒 Статус: модель `Equipment` считается **завершённой**
>
> Дата фиксации: **2026-07-15**. Версия: **v1**.
>
> Дальнейшее развитие раздела выполняется **исключительно наполнением данными**.
> Изменение Prisma-схемы для `Equipment` / `EquipmentSpec` допускается **только**
> при обнаружении архитектурной ошибки — и только через отдельное архитектурное
> решение с обновлением этого документа.

## 1. Что разрешено и что запрещено

### ✅ Разрешено (без архитектурного решения)

- добавлять **оборудование** (любое количество, любых классов);
- добавлять **характеристики** через `EquipmentSpec`;
- добавлять **фотографии** (`images`);
- добавлять **PDF** и документацию (`manuals`);
- добавлять **связи** с клиниками, врачами, заболеваниями, процедурами;
- менять отображение (UI), не трогая модель.

### ❌ Не допускается

- изменение существующих полей `Equipment`;
- создание **альтернативных моделей оборудования** (например, отдельной модели под
  диагностику или под лазеры);
- изменение структуры `Equipment` / `EquipmentSpec` без отдельного архитектурного
  решения;
- добавление полей под конкретный аппарат (это ровно то, от чего защищает
  `EquipmentSpec`).

## 2. Структура `Equipment`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `String` | PK, cuid |
| `slug` | `String` @unique | URL: `/equipment/[slug]` |
| `title` | `String` | Название (напр. «ZEISS VisuMax 800») |
| `summary` | `String?` | Краткое описание (карточки, meta) |
| `description` | `String?` | Полное описание |
| `manufacturer` | `String?` | Производитель («Carl Zeiss Meditec AG») |
| `country` | `String?` | Страна производства |
| `year` | `Int?` | Год появления модели — **только если достоверно известен** |
| `principle` | `String?` | Принцип работы |
| `advantages` | `String[]` | Преимущества |
| `indications` | `String[]` | Показания |
| `limitations` | `String[]` | Ограничения / условия эксплуатации |
| `images` | `String[]` | Локальные пути: `/equipment/<slug>/<file>` |
| `manuals` | `String[]` | Локальные пути к PDF |
| `categoryId` | `String?` | FK → `EquipmentCategory` (= тип оборудования) |
| `supplierId` | `String?` | FK → `Supplier` |
| `createdAt` / `updatedAt` | `DateTime` | Служебные |

**PDF и изображения в БД не хранятся** — только пути к файлам в `public/`.

## 3. `EquipmentSpec` — почему именно она

### 3.1 Структура

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `String` | PK |
| `equipmentId` | `String` | FK → `Equipment` (`Cascade`) |
| `group` | `String?` | Группа: «Оптические данные», «Габариты и масса» |
| `label` | `String` | Параметр: «Длина волны» |
| `value` | `String` | Значение: «1043 нм» |
| `sortOrder` | `Int` = 0 | Порядок вывода |

Ограничения: `@@unique([equipmentId, label])`, `@@index([equipmentId, sortOrder])`.

### 3.2 Обоснование

Технические характеристики офтальмологического оборудования **несопоставимы между
классами приборов**:

| Класс | Характерные параметры |
|---|---|
| Фемтосекундный лазер | длина волны, частота импульсов, длительность импульса |
| Эксимерный лазер | длина волны 193 нм, зона абляции |
| ОКТ | тип сканирования, разрешение, скорость A-сканов |
| Биометр | метод измерения, точность |
| Микроскоп | увеличение, тип освещения |
| Витреосистема | частота реза, вакуум |

Альтернативы и почему они отвергнуты:

| Вариант | Почему нет |
|---|---|
| Колонки под каждый параметр | Схема росла бы под **каждый новый аппарат**. Сотни nullable-колонок, 95% пустых |
| `Json`-поле | Непрозрачно, нет валидации, нельзя гарантировать порядок и группировку, не запросить |
| Отдельная модель на класс прибора | Дублирование связей и логики; каталог перестал бы быть однородным |
| **`EquipmentSpec` (group/label/value)** | ✅ Универсально для любого класса, схема не растёт, порядок и группировка сохранены, идемпотентный upsert по `@@unique([equipmentId, label])` |

**`EquipmentSpec` — это то, что делает модель `Equipment` замораживаемой.**
Любая характеристика любого прибора кладётся в неё без изменения схемы.

### 3.3 Пример

| group | label | value |
|---|---|---|
| Оптические данные | Длина волны | 1043 нм |
| Оптические данные | Максимальная частота повторения импульсов | 2 МГц |
| Хирургический микроскоп | Увеличение | 0,7× |
| Условия эксплуатации | Температура | +18 °C…+25 °C |
| Габариты и масса | Масса устройства | 520 кг |

## 4. Связи

| Связь | Тип | Таблица |
|---|---|---|
| → `EquipmentCategory` | прямая | `categoryId` (`SetNull`) |
| → `Supplier` | прямая | `supplierId` (`SetNull`) |
| → `EquipmentSpec` | прямая 1:N | `EquipmentSpec.equipmentId` (`Cascade`) |
| ↔ `Clinic` | прямая | `ClinicOnEquipment` |
| ↔ `Doctor` | прямая | `DoctorOnEquipment` |
| ↔ `Disease` | прямая | `DiseaseOnEquipment` |
| ↔ `Procedure` | прямая | `ProcedureOnEquipment` |

Все связи двусторонние: страница оборудования показывает клиники / процедуры /
заболевания / врачей, и каждая из этих страниц показывает оборудование.

### 4.1 Связь `Equipment → ScientificWork` НЕ создаётся

Архитектурное решение:

- `ScientificWork` описывает **научную деятельность врача** (диссертация, патент, статья).
  Её владелец — врач (`doctorId` NOT NULL).
- Оборудование — **самостоятельная сущность**, у него нет автора.

Если понадобится хранить исследования конкретного аппарата — создаётся **новая
сущность `ClinicalStudy`**:

```
Equipment → ClinicalStudy        ✅ правильный путь
Equipment → ScientificWork       ❌ не делать
```

Переиспользовать `ScientificWork` для этого нельзя: это разные предметные области,
и связь исказила бы смысл обеих сущностей.

## 5. Подтверждение масштабируемости

Проверено эмпирически: следующие аппараты добавляются **только данными**, без единого
изменения Prisma-схемы.

| Аппарат | Производитель | Категория | Только данные? |
|---|---|---|---|
| ZEISS MEL 90 | Carl Zeiss Meditec | Лазерные системы | ✅ |
| ZEISS VISULAS YAG III | Carl Zeiss Meditec | Лазерные системы | ✅ |
| ZEISS IOLMaster 700 | Carl Zeiss Meditec | Диагностическое оборудование | ✅ |
| ZEISS CIRRUS 6000 | Carl Zeiss Meditec | Диагностическое оборудование | ✅ |
| OCULUS Pentacam AXL | OCULUS Optikgeräte | Диагностическое оборудование | ✅ |
| Haag-Streit Lenstar | Haag-Streit | Диагностическое оборудование | ✅ |
| ZEISS OPMI Lumera | Carl Zeiss Meditec | Хирургическое оборудование | ✅ |
| Alcon Constellation Vision System | Alcon | Хирургическое оборудование | ✅ |

Покрываемые классы: лазеры (фемто, эксимерные, YAG), микроскопы, OCT, биометры,
томографы, диагностические комплексы, хирургические системы.

**Что делает это возможным:**
1. `EquipmentCategory` — тип прибора справочником, а не полем в схеме;
2. `EquipmentSpec` — любые характеристики без новых колонок;
3. `manufacturer` / `country` — строки, любой вендор;
4. join-таблицы связей универсальны и не зависят от класса прибора;
5. `images` / `manuals` — массивы путей, любое количество файлов.

**Если для добавления аппарата потребуется изменить схему — это сигнал об
архитектурной ошибке.** Такой случай разбирается отдельно, а не «дополняется по-тихому».

## 6. Правила наполнения

1. **Не придумывать.** Нет достоверного источника — поле пустое.
   Пример: у `ZEISS VisuMax 800` поле `year` пустое — год выпуска модели не подтверждён
   ни брошюрой производителя, ни сайтом ZEISS.
2. **Технические характеристики — только из официальной документации** производителя.
   Маркетинговые заявления клиник в `EquipmentSpec` не попадают.
3. **Файлы только локальные**: `public/equipment/<slug>/`. Внешние URL запрещены.
4. **Связи — по документации.** `Equipment ↔ Procedure` создаётся, если процедура
   указана производителем среди поддерживаемых.
5. При расхождении источников (например, международная и региональная версии
   документации различаются по показаниям) — брать пересечение, а расхождение
   отражать текстом в `indications`.

## 7. Правила отображения

Страница `/equipment/[slug]`:

Hero (фото, производитель, страна, тип, год) → Описание → Принцип работы →
Преимущества → Показания → Ограничения → Технические характеристики (таблица,
сгруппированная по `EquipmentSpec.group`) → Галерея → Документы.
Сайдбар: Используется в клиниках / для процедур / при заболеваниях / Работают врачи.

**Изображения:** место резервируется через CSS `aspect-ratio` (CLS = 0) — пиксельные
размеры в БД **не хранятся**, иначе каждое новое фото требовало бы правки схемы.
Галерея — `loading="lazy"`, hero — `fetchPriority="high"` (LCP).

**Производительность:** загрузка страницы — константа **12 SQL-запросов**, не зависит
от количества связей (проверено: 23 связи → 12 запросов, 135 связей → 12 запросов).
Батчинг Prisma через `IN`, N+1 отсутствует. Страница ISR-кэширована (`revalidate=3600`).
