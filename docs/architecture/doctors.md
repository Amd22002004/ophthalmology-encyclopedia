# Модель `Doctor`

> Статус: **v1, заморожено**. Сверено с `prisma/schema.prisma`.

## 1. Структура

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `String` | PK, cuid |
| `slug` | `String` @unique | URL: `/doctors/[slug]`. Формат: `familiya-imya-otchestvo` (транслит) |
| `firstName` | `String` | Имя (обязательно) |
| `lastName` | `String` | Фамилия (обязательно) |
| `middleName` | `String?` | Отчество |
| `photoUrl` | `String?` | Путь к локальному фото: `/doctors/<file>` |
| `position` | `String?` | Публичная должность / специализация — заголовок карточки |
| `category` | `String?` | Группа специализации для фильтрации (напр. «Окулопластика») |
| `credo` | `String?` | Краткое резюме: ключевые операции и направления |
| `prodoctorovUrl` | `String?` | Профиль на prodoctorov.ru |
| `siteUrl` | `String?` | Профиль на сайте клиники |
| `bio` | `String?` | Биография / экспертиза |
| `career` | `String?` | Карьера и образование (единым текстом) |
| `experienceYears` | `Int?` | Стаж, лет |
| `region` | `String?` | Регион строкой — **legacy**, см. §5 |
| `regionId` | `String?` | FK → `Region` |
| `createdAt` / `updatedAt` | `DateTime` | Служебные |

### Важно про `position` и `category`

Это **разные** поля, их нельзя путать:
- `position` — то, что показывается пользователю («Заведующий рефракционным отделением»);
- `category` — техническая группа для фильтрации («Рефракционная хирургия»).

`category` **не** является квалификационной категорией врача («высшая категория»).
Поля для квалификационной категории в модели **нет**.

## 3. Правила отображения

### 3.1 Страница врача `/doctors/[slug]`

Порядок блоков (шаблон `doctor-template.tsx`):

1. **Шапка** — фото 118×150, бейдж сети (из `clinics[].clinic.networkName`), H1 ФИО,
   специальности, `position`, стаж, CTA.
   CTA `href = prodoctorovUrl ?? siteUrl` — кнопка не исчезает, если есть хотя бы одна ссылка.
2. **Экспертиза** — `bio` + `credo` (курсивом, в кавычках).
3. **Научная деятельность** — блок из `scientificWorks` (см. §3.3).
4. **Основные направления** — `diseases` пилюлями-ссылками.
5. **Выполняемые операции и процедуры** — `procedures` строками-ссылками.
6. **Работает на оборудовании** — `equipment`.
7. **Образование и карьера** — `career`.
8. **Сайдбар:** «Работает в клиниках», «Связанные страницы энциклопедии».
9. **Граф** «Связи в энциклопедии».

Пустые блоки не рендерятся. Сайдбар и его 300px-колонка не резервируются, если он пуст.

### 3.2 Карточка врача (каталог `/doctors`)

Состав: фото 58×72 слева, ФИО, `position`, стаж, «Направления · в энциклопедии»
(пилюли, максимум 3 + `+N`), «Принимает: города», «Подробнее →».

### 3.3 Блок «Научная деятельность»

UI общий со страницей `/publications/[slug]` — компоненты вынесены в
`src/components/entity/scientific-work-ui.tsx` (`InfoField`, `NoveltyCard`,
`PracticalCard`, `ResultCard`, `DocCard`). **Не дублировать их локально** — иначе
оформление разделов разойдётся.

Состав: бейдж «Научная деятельность» → тип работы → инфо-блок (Автор / Тема / Место
защиты / Научный руководитель / Специальность ВАК / Публикации) → Аннотация →
Научная новизна → Практическая значимость → Основные результаты (метрики) →
Документы исследования → «Подробнее о работе →».

## 4. Правила наполнения

1. **Не придумывать данные.** Нет достоверного источника — поле пустое.
2. **Фото — только локальные** (`public/doctors/`). Внешние URL запрещены.
3. `photoUrl` в seed **не перезаписывается** при обновлении — чтобы не затирать
   вручную загруженные фото.
4. Связи `Doctor → Disease/Procedure` означают **направления работы врача**.
   Не путать с темами научных работ (см. [`graph-model.md`](./graph-model.md) §4.2).
5. Связь `Doctor → Equipment` создаётся только при прямом подтверждении
   («работает на данном аппарате»), а не по косвенным признакам.

## 5. Известный технический долг

| Проблема | Описание |
|---|---|
| Дублирование региона | Есть `region: String?` и `regionId → Region`. Источник истины — `regionId`; строковое поле legacy |
| Нет квалификационной категории | «Высшая категория» негде хранить. `category` занята под группу фильтрации |
| Нет отдельных «Сертификатов» / «Образования» | Есть только `career` единым текстом |
| Нет счётчика отзывов | `prodoctorovUrl` хранит ссылку, но не число отзывов |

Эти пункты — кандидаты на будущее архитектурное решение, а не на молчаливое расширение.

## 6. SEO

- Заголовок страницы: `createPageMetadata`, canonical `/doctors/[slug]`.
- H1 — ФИО. Заголовки блоков — реальные `h3`/`h4`/`h5` (индексируются).
- В `h4` научной работы входят тип, степень и название — все индексируются.
- Хлебные крошки: `Главная › Врачи и специалисты › Фамилия И. О.`
- Schema.org: `Physician` (`name`, `url`, `jobTitle`, `worksFor[]`) + `BreadcrumbList`.
- Изображения: `loading="lazy"` + `decoding="async"`; размер зарезервирован классами.
