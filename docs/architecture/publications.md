# Публикации: `ScientificWork` vs `Publication`

> Статус: **v1.4.1 — подтверждённая публикация корпуса Островерхова**.
> Архитектурное решение, локальная синхронизация БД, повторный seed и технические
> проверки зафиксированы 2026-08-13. Каноническое отчество «Иванович» и разрешение
> на распространение переданных материалов подтверждены пользователем.
> Фактическая структура полей задаётся `prisma/schema.prisma`, а этот документ —
> SSOT семантики публикации научных работ.

## 1. Главное

В разделе `/publications` живут две разные сущности:

- `ScientificWork` — научная работа врача проекта: статья, диссертация, патент,
  методические рекомендации или монография;
- `Publication` — редакционный материал энциклопедии или внешний журнальный текст.

Данные между ними не копируются. `ScientificWork` принадлежит врачу через
обязательный `doctorId`, а полный библиографический список авторов хранит отдельно
в `authors`. Стабильный `slug` только адресует запись и сам по себе её не публикует.

## 2. Почему это разные сущности

| | `ScientificWork` | `Publication` |
|---|---|---|
| Природа | Научная деятельность врача | Редакционный контент |
| Владелец | `doctorId` обязателен, удаление врача — `Cascade` | `doctorId` nullable, удаление врача — `SetNull` |
| Авторство | Упорядоченный `authors[]`; `doctorId` связывает работу с графом | Связанный врач или строковый `authorName` |
| Специфика | Библиография, источник, тип исследования, результаты, документы | Аннотация и редакционный `content` |
| Полный текст | Только ссылка на файл или первоисточник | Может храниться в `content` |

Объединение нарушило бы инвариант обязательного владельца научной работы и создало
бы множество взаимоисключающих nullable-полей.

## 3. Когда что использовать

| Материал | Сущность |
|---|---|
| Кандидатская или докторская диссертация | `ScientificWork` |
| Автореферат | `ScientificWork` |
| Патент, методические рекомендации, монография | `ScientificWork` |
| Научная статья врача проекта | `ScientificWork` |
| Обзорная статья энциклопедии | `Publication` |
| Редакционный материал | `Publication` |
| Работа внешнего автора без врача-владельца в проекте | `Publication` |

`doctorId` не означает, что связанный врач — единственный или первый автор.
Библиографическое авторство нельзя восстанавливать из графа: оно берётся из
первичного источника и сохраняется в исходном порядке в `authors`.

## 4. SSOT и единый тип каталога

У факта один владелец: научная работа существует только в `ScientificWork`, без
копии в `Publication`. Каталог читает владельцев данных и приводит их к единому
UI-типу `PublicationCatalogItem`; этот тип не хранится в БД.

Новая работа не должна автоматически появляться в каталоге только потому, что seed
создал запись. Prisma-загрузчики обязаны применять gate из
`src/lib/scientific-work-publication.ts`; raw SQL-поиск воспроизводит тот же контракт
явными условиями и проверяется отдельным тестом на расхождение.

## 5. Контракт `ScientificWork`

### 5.1 Идентификация и авторство

| Поле | Назначение |
|---|---|
| `id` | Первичный ключ |
| `slug String? @unique` | Адрес `/publications/[slug]`; nullable для legacy-совместимости |
| `doctorId` | Обязательный FK на врача-владельца в графе |
| `type` | Публичное название типа работы |
| `contentKind` | Структурный тип контента для корректного шаблона |
| `title` | Полное название |
| `authors String[]` | Все авторы в порядке первичного источника |
| `year` | Год работы или публикации, не дата публикации страницы сайта |
| `sortOrder` | Порядок в списке научных работ врача |

Nullable `slug` остаётся техническим долгом аддитивной миграции. Компенсация —
обязательная проверка `slug != null` в публичном gate.

### 5.2 Библиография и первоисточник

| Поле | Назначение |
|---|---|
| `bibliography` | Готовая библиографическая ссылка |
| `journal`, `volume`, `issue`, `pages` | Структурированные реквизиты журнала |
| `doi @unique` | DOI, если подтверждён |
| `sourcePageUrl` | Страница работы у издателя или владельца источника |
| `sourcePdfUrl` | Внешняя ссылка на PDF у издателя |
| `sourceStatus` | Полнота найденного первичного материала, но не публикационный статус |
| `sourceNote` | Нейтральное пояснение границ источника |

### 5.3 Содержание

| Поле | Назначение |
|---|---|
| `topic` | Тема из первичного документа |
| `summary` | Краткое аккуратное описание |
| `novelty` | Для статьи — «Актуальность»; для диссертации — научная новизна |
| `practicalValue` | Для статьи — методы/методика; для диссертации — практическая значимость |
| `results` | Результаты, дословно проверяемые по источнику |
| `conclusions` | Вывод или практическое значение с границами исследования |
| `degree`, `speciality`, `organization`, `supervisor` | Квалификационные реквизиты, когда применимы |

Названия блоков определяет `contentKind`; одно и то же поле не должно выдавать обзор
за клиническое исследование или библиографическую карточку за пересказ результатов.

### 5.4 Файлы, права и SEO

| Поле | Назначение |
|---|---|
| `pdfUrl` | Локальная копия полного текста |
| `abstractUrl` | Локальная копия автореферата |
| `images` | Локальные иллюстрации из первичного документа |
| `rightsVerifiedAt` | Дата подтверждения прав на локальное размещение |
| `rightsBasis` | Структурированное основание: лицензия, разрешение автора/издателя или public domain |
| `rightsNote` | Документированное основание проверки прав |
| `publicationBlockReason` | Явный редакционный блокер, не обходится флагом `isPublished` |
| `seoTitle`, `seoDescription` | Проверенные SEO-проекции страницы |

`sourcePageUrl` и `sourcePdfUrl` ведут к владельцу первоисточника и не означают, что
сайт получил право хранить копию. `pdfUrl`, `abstractUrl` и `images` считаются
локальными ассетами и не допускаются в публичный вывод без одновременного заполнения
`rightsVerifiedAt` и `rightsBasis != UNVERIFIED`. `rightsNote` сохраняет реквизиты
лицензии или разрешения; одна дата не является достаточным основанием.

## 6. Статус источника

`ScientificWorkSourceStatus` отвечает только на вопрос, какой первичный материал
фактически найден и проверен.

| Значение | Семантика |
|---|---|
| `FULL_TEXT` | Доступен полный текст работы |
| `EXTRACTED_PAGES` | Доступны релевантные страницы, извлечённые из полного выпуска |
| `SCANNED_PAGES` | Доступны сканированные страницы работы |
| `BIBLIOGRAPHIC_ONLY` | Подтверждены только библиографические данные; полного текста нет |

Эти значения не эквивалентны `isPublished`, не подтверждают права и не выражают
уровень научной доказательности.

## 7. Тип содержания

`ScientificWorkContentKind` управляет семантикой разделов страницы:

| Значение | Правило отображения |
|---|---|
| `ORIGINAL_RESEARCH` | Актуальность → материалы и методы → результаты → вывод |
| `CLINICAL_CASE` | Актуальность → клинический случай и методика → результаты → вывод |
| `REVIEW` | Актуальность → обзор/направления применения → положения → вывод |
| `THESIS` | Аннотация → научная новизна → методы → основные результаты → вывод |
| `OTHER` | Нейтральный универсальный набор заголовков |

`contentKind` не доказывает содержание. Тип выбирается только после чтения
первоисточника; для `BIBLIOGRAPHIC_ONLY` исследовательские блоки всё равно скрыты.

## 8. Единый publication gate

Публичный Prisma-фильтр `publicScientificWorkWhere(now)` является SSOT для
видимости `ScientificWork`. Запись публична только при одновременном выполнении:

1. `slug` задан и не пуст;
2. `isPublished = true`;
3. `publishedAt != null` и дата уже наступила;
4. `evidenceValidatedAt != null`;
5. `publicationBlockReason = null`;
6. локальных ассетов нет **или** одновременно заполнены `rightsVerifiedAt` и
   структурированное основание `rightsBasis != UNVERIFIED`;
7. соблюдены дополнительные ограничения `BIBLIOGRAPHIC_ONLY`.

`sourcePageUrl` и `sourcePdfUrl` предназначены только для внешних HTTPS-ссылок
первоисточника. Локальные пути в этих полях запрещены: они не могут обходить
проверку прав, предусмотренную для `pdfUrl`, `abstractUrl` и `images`.

Gate обязан применяться не только в detail-route, но и во всех проекциях:

- каталог `/publications` и прямой `/publications/[slug]`;
- блок научных работ врача;
- обратные связи заболеваний, процедур, оборудования и клиник автора;
- связанные работы;
- поиск;
- счётчики сущностей;
- sitemap и индексируемые SEO-проекции.

Скрытая запись не должна просачиваться через обратную связь. Прямой URL такой
работы возвращает `404`, а не страницу черновика. Локальные файлы требуют отдельной
проверки доступности: отсутствие кнопки в UI не закрывает уже существующий прямой
URL в `public/`.

## 9. Инвариант `BIBLIOGRAPHIC_ONLY`

Библиографическая карточка допустима, но не имитирует прочитанное исследование.
Для неё обязательны:

- `pdfUrl = null`;
- `abstractUrl = null`;
- `sourcePdfUrl = null`;
- пустой `images`;
- пустые `novelty`, `practicalValue`, `results`, `conclusions`;
- явный `sourceNote`, что полный текст не найден и карточка составлена по
  библиографическим данным.

Разрешены подтверждённые реквизиты: название, авторы, год, тип, журнал или
организация, том/номер/страницы, DOI и ссылка на карточку источника. `summary` не
может реконструировать методы, результаты или выводы по косвенным упоминаниям.

Кнопка скачивания PDF и исследовательские разделы для такого статуса запрещены.
Переход к полноценной карточке выполняется только после получения и проверки
текста, смены `sourceStatus` и повторного `evidence-validation`.

## 10. Связи графа

```text
ScientificWork
 ├─→ Doctor       прямая, обязательная; владелец работы в графе
 ├─↔ Disease      прямая; только реально исследуемое заболевание
 ├─↔ Procedure    прямая; только реально исследуемая методика
 ├─↔ Equipment    прямая; только прямо указанная модель/инструмент
 └─→ Clinic       вычисляемая через автора; UI: «Клиники автора»
```

Медицинские связи не выводятся из профиля врача. Наличие общего слова в названии не
заменяет первичный источник. Для библиографической карточки связь допустима только
когда сам библиографический источник однозначно подтверждает её; при сомнении связь
не создаётся.

## 11. Страница и документы

Страница полной работы показывает H1, тип, год, журнал/организацию, всех авторов,
библиографию, источник, DOI, краткое описание и секции согласно `contentKind`.
Sidebar отделяет автора-владельца от списка соавторов и явно называет вычисляемую
связь «Клиники автора».

Документы различаются по роли:

- локальный `pdfUrl` после проверки прав — действие «Скачать PDF»;
- `sourcePdfUrl` — ссылка «PDF на сайте издателя»;
- `sourcePageUrl` — «Страница первоисточника»;
- DOI — кликабельный идентификатор.

Изображения выводятся только из проверенного первичного документа и только после
проверки прав. Нейтральное оформление предпочтительнее придуманной иллюстрации.

## 12. SEO

- canonical: `/publications/[slug]`;
- `seoTitle` может задавать абсолютный title без повторного добавления общего
  шаблона сайта;
- description фиксирует тип, год, источник и тему без рекламных обещаний;
- Schema.org использует `ScholarlyArticle` для статей и `Thesis` для диссертации,
  упорядоченный список авторов, иерархию Periodical → PublicationVolume →
  PublicationIssue, DOI и только разрешённые локальные encoding/image;
- скрытые работы отсутствуют в sitemap, поиске, счётчиках и JSON-LD.

разрешение на распространение; основание сохранено как

Диссертация 2023 года заполнена по найденным полному тексту и автореферату. Их
титульные листы подтверждают «Александр Иванович», специальность, организации и
научного руководителя. Пользователь подтвердил каноническое отчество «Иванович»;
на странице доступны кнопки полного текста и автореферата.

Единственное содержательное ограничение корпуса — статья 2018 года: она публична

PDF-кнопку до получения страниц 61–63.

## 14. Ограничения и уникальность

- `@@unique([doctorId, title])` — у врача нет двух работ с одинаковым названием;
- `doi @unique` — один DOI не дублируется;
- `@@unique(slug)` — один публичный адрес;
- `@@index([doctorId, sortOrder])`, `@@index([year])`,
   `@@index([isPublished, evidenceValidatedAt, publishedAt, publicationBlockReason])` и
  `@@index([sourceStatus])` поддерживают основные выборки;
- изменение gate, source semantics или правил локальных прав требует нового
  архитектурного решения и одновременного обновления этого документа.
