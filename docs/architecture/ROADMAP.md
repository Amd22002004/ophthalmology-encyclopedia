## Как читать статусы

| Знак | Значение |
|---|---|
| ✅ | Механизм готов: модель + маршрут + шаблон + связи в графе |
| 🟡 | Механизм готов, идёт наполнение данными |
| ⬜ | Не начато |

**Важно:** ✅ означает готовность **механизма**, а не полноту данных.
Наполнение отслеживается отдельной колонкой — это разные вещи.

## 1. Реализовано

### Архитектура и платформа

- ✅ **Граф знаний энциклопедии** — 39 моделей, 20 связующих таблиц, двусторонняя перелинковка
- ✅ **Entity First** — каждая сущность имеет `slug`, страницу и место в графе
- ✅ **SEO-перелинковка** — canonical, OpenGraph, Schema.org, sitemap, индексируемые заголовки
- ✅ **Архитектурная документация v1** — 9 документов, модель заморожена
- ✅ **Идемпотентный seed** — составные PK + upsert, повторный прогон не создаёт дублей
- ✅ **Регламент безопасного деплоя** — `migrate diff` → аддитивный SQL → build → PM2
- ✅ **Админ-панель (MVP)** — авторизация, редактор клиник

### Ключевые механизмы

- ✅ **`EquipmentSpec`** — характеристики любого прибора без изменения схемы
- ✅ **`ScientificWork`** — научная работа как полноценная сущность энциклопедии
- ✅ **Автопоявление работ** — новая работа врача попадает в каталог без единой строки кода
- ✅ **Достоверность связей** — прямые связи работы вместо ложных транзитивных
- ✅ **Локальные ассеты** — фото и PDF только из `public/`, внешних URL нет

### Приоритет наполнения

Наибольшая отдача для графа знаний сейчас:

1. **`DiseaseOnProcedure`** — 0 связей. Это базовая ось энциклопедии («чем лечится
   заболевание»); без неё страницы заболеваний и процедур не связаны между собой.
2. **`ClinicOnDisease` / `ClinicOnProcedure`** — 0 связей. Клиники не связаны с тем,
   что лечат.
3. **Научные работы остальных врачей** — раздел построен, но живёт на одной записи.
4. **Оборудование** — механизм доказан, нужен объём.

## 3. Следующий этап

Крупные направления, не начатые. Каждое требует **отдельного архитектурного решения**
(новая сущность = новая запись в [`graph-model.md`](./graph-model.md)).

| Направление | Что потребуется |
|---|---|
| ⬜ **Производители оборудования** | Новая сущность `Manufacturer`. Сейчас производитель — строка `Equipment.manufacturer`, отдельной сущности **нет** |
| ⬜ **Лекарственные препараты** | Новая сущность + связи с заболеваниями и процедурами |
| ⬜ **Международные исследования** | Новая сущность `ClinicalStudy` (в т.ч. `Equipment → ClinicalStudy`) |
| ⬜ **Диагностические алгоритмы** | Новая сущность + связи с заболеваниями |
| ⬜ **Атлас изображений** | Новая сущность (медиа) + связи с заболеваниями |
| ⬜ **Видео** | Новая сущность (медиа) + связи с процедурами и врачами |
| ⬜ **AI-помощник врача** | Слой поверх готового графа знаний |
| ⬜ **AI-помощник пациента** | Слой поверх готового графа знаний |

**Замечание по AI-помощникам:** граф знаний — их фундамент. Достоверность связей,
заложенная в v1, определяет качество ответов. Ложная связь в графе станет ложным
ответом ассистента — поэтому принцип «только достоверные связи» критичен именно здесь.

## 4. Долгосрочная цель

> Создать крупнейшую русскоязычную офтальмологическую энциклопедию с полноценным
> графом знаний между врачами, клиниками, заболеваниями, процедурами, оборудованием,
> научными работами и публикациями.

Что отличает её от типового каталога клиник:

1. **Каждая сущность — узел графа**, а не строка в списке.
2. **Связи достоверны.** Ложная связь не добавляется никогда — пустой раздел честнее.
3. **Научный слой.** Диссертации и исследования врачей — полноценные страницы
   энциклопедии, связанные с заболеваниями и методиками, которые в них исследуются.
4. **Оборудование как сущность.** Аппарат связан с клиниками, врачами, процедурами и
   заболеваниями — а не упомянут строкой в описании клиники.
5. **Архитектура выдерживает объём.** Модель заморожена: сотни единиц оборудования и
   научных работ добавляются данными, без изменения схемы.
